# Lab5 用户程序实验分工

## 一、分工目标

本分工覆盖指导书 Lab5 的全部编程任务、分支任务和报告任务，包括：

- 功能模块一：用户态系统调用
- 功能模块二：创建并加载第一个用户进程
- 功能模块三：复制用户进程
- 功能模块四：进程退出、让出和终止
- `RESTORE_ALL` 的用户态/内核态双向返回
- COW Challenge 及测试、有限状态机说明、Dirty COW 分析
- “用户程序何时预加载”的说明题
- GDB 调试 `ecall/sret` 分支任务
- 实验报告七项要求、各练习的 spec/prompt 与 bug 记录
- 三种工具链下的编译、运行和最终验收

本分工按三条纵向功能链划分。每条链尽量由一个人从实现、调试一直负责到报告，减少同一个函数反复换负责人。

## 二、总体工作量

按“编码 + 调试 + 测试 + 报告”综合估算，完成全部任务约需 145～155 人时。

## 六、交界点与联调次数

固定代码接口共 3 个，正式联调共 3 次。日常 Git 提交和合并次数不限，但不单独计为交界。

### 接口 1：trap ABI

Day 0 冻结以下约定：

- `struct trapframe` 的字段布局
- `trapframe` 在栈上的位置
- `__trapret` 与 `forkrets` 的入口规则
- 用户态寄存器保存和恢复顺序
- `exception_handler` 的调用约定

负责人：罗茜。  
其他成员只在接口变化时参与评审。

### 接口 2：COW 缺页处理

罗茜在 `exception_handler` 中识别用户态缺页，并调用贺佳怡提供的 COW helper：

```c
int do_pgfault(struct mm_struct *mm, uintptr_t addr, uint32_t error_code);
```

该函数的具体名称可在 Day 0 按现有代码调整，但函数签名和调用方只确定一次。

- 缺页入口和异常判断：罗茜
- COW 页复制、页表更新、引用计数：贺佳怡

这是唯一需要跨 trap 与内存管理模块的接口。

### 接口 3：进程管理公共接口

以下函数签名在 Day 0 冻结：

```c
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
int do_exit(int error_code);
int do_yield(void);
int do_execve(const char *name, size_t len,
              unsigned char *binary, size_t size);
int do_wait(int pid, int *code_store);
int do_kill(int pid);
```

系统调用层只调用这些接口，不直接操作进程内部数据结构。调用方为罗茜，具体语义实现由对应函数负责人完成。

### 正式联调安排

1. **Day 0 接口冻结**
   - 恢复 lab2/3/4 前置代码
   - 确认空骨架、工具链和 `make` 目标
   - 冻结 trapframe、COW helper 和 `do_*` 签名

2. **COW 接入联调**
   - 普通 fork 的全部测试先通过
   - 贺佳怡接入 COW helper
   - 罗茜确认缺页异常能够进入 COW 路径
   - 只在该阶段共同调试一次

3. **最终集成验收**
   - 石欣哲和贺佳怡完成各自主链路
   - 罗茜执行全量回归
   - 出现问题时按函数所有权退回负责人
   - 完成报告、日志和提交检查

## 十、Git 协作规则

- 建议为三人分别建立功能分支，不直接在主分支开发。
