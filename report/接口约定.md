## 3. Trapframe ABI

### 3.1 内存布局

`struct trapframe` 必须与汇编保存顺序完全一致。`sp` 指向 trapframe 起始地址，所有偏移以字节为单位。

| 偏移 | 字段 | 说明 |
|---:|---|---|
| 0 | `gpr.zero` | `x0` |
| 8 | `gpr.ra` | `x1` |
| 16 | `gpr.sp` | `x2`，用户态发生 trap 时是用户栈指针 |
| 24 | `gpr.gp` | `x3` |
| 32 | `gpr.tp` | `x4` |
| 40 | `gpr.t0` | `x5` |
| 48 | `gpr.t1` | `x6` |
| 56 | `gpr.t2` | `x7` |
| 64 | `gpr.s0` | `x8` |
| 72 | `gpr.s1` | `x9` |
| 80 | `gpr.a0` | `x10`，系统调用号及返回值 |
| 88 | `gpr.a1` | `x11` |
| 96 | `gpr.a2` | `x12` |
| 104 | `gpr.a3` | `x13` |
| 112 | `gpr.a4` | `x14` |
| 120 | `gpr.a5` | `x15` |
| 128 | `gpr.a6` | `x16` |
| 136 | `gpr.a7` | `x17` |
| 144 | `gpr.s2` | `x18` |
| 152 | `gpr.s3` | `x19` |
| 160 | `gpr.s4` | `x20` |
| 168 | `gpr.s5` | `x21` |
| 176 | `gpr.s6` | `x22` |
| 184 | `gpr.s7` | `x23` |
| 192 | `gpr.s8` | `x24` |
| 200 | `gpr.s9` | `x25` |
| 208 | `gpr.s10` | `x26` |
| 216 | `gpr.s11` | `x27` |
| 224 | `gpr.t3` | `x28` |
| 232 | `gpr.t4` | `x29` |
| 240 | `gpr.t5` | `x30` |
| 248 | `gpr.t6` | `x31` |
| 256 | `status` | 保存的 `sstatus` |
| 264 | `epc` | 保存的 `sepc` |
| 272 | `tval` | 保存的 `stval` |
| 280 | `cause` | 保存的 `scause` |

整个 trapframe 为 288 字节，即 `36 * 8`。

### 3.2 `sscratch` 约定

- 用户态运行期间，`sscratch` 保存该进程的内核栈顶。
- 内核态运行期间，`sscratch` 为 0。
- 从用户态进入内核时，切换并保存用户栈指针。
- 从内核态返回用户态前，把下次 trap 所需的内核栈顶写回 `sscratch`。
- 从内核态 trap 返回内核态时，不能错误覆盖当前内核栈。

### 3.3 入口与返回

`__alltraps` 的调用约定：

```asm
__alltraps:
    SAVE_ALL
    mv a0, sp
    jal trap
    # a0 返回后 sp 必须仍指向同一个 trapframe
```

`__trapret` 的返回约定：

```asm
__trapret:
    RESTORE_ALL
    sret
```

`forkrets` 的调用约定：

```c
forkrets(struct trapframe *tf);
```

参数 `tf` 是新进程的内核栈 trapframe 地址。调用后，新进程从该 trapframe 的 `epc` 恢复执行。`forkrets` 不返回普通 C 调用者。

### 3.4 Trapframe 修改规则

- `pushregs` 字段顺序、`trapframe` 字段顺序和汇编偏移不得单独修改。
- 新增字段只能加在 `cause` 之后，并同步修改 `SAVE_ALL/RESTORE_ALL`、偏移和本节文档。
- 系统调用返回值写入 `current->tf->gpr.a0`。
- 系统调用返回前必须执行 `current->tf->epc += 4`，避免重复执行同一条 `ecall`。

## 4. 异常处理接口

公开函数：

```c
void exception_handler(struct trapframe *tf);
```

处理规则：

| 异常 | 动作 |
|---|---|
| `CAUSE_USER_ECALL` | `tf->epc += 4; syscall();` |
| `CAUSE_LOAD_PAGE_FAULT` | 调用 `do_pgfault`，错误码包含 `PFAULT_USER` |
| `CAUSE_STORE_PAGE_FAULT` | 调用 `do_pgfault`，错误码包含 `PFAULT_USER | PFAULT_WRITE` |
| `CAUSE_FETCH_PAGE_FAULT` | 当前用户程序不使用按需代码页时视为致命异常 |
| 其他异常 | 打印 trapframe，并进入内核错误处理 |

缺页调用方为罗茜，实现方为贺佳怡：

```c
int ret = do_pgfault(current->mm, error_code, tf->tval);
```

返回值：

- `0`：缺页已经处理，可以返回用户态继续执行。
- 负数：处理失败，进入错误处理。

## 5. 缺页错误码与 COW 标志

### 5.1 `error_code`

在 `vmm.h` 中固定以下软件错误位：

```c
#define PFAULT_PRESENT 0x1
#define PFAULT_WRITE   0x2
#define PFAULT_USER    0x4
```

含义：

- `PFAULT_PRESENT`：导致异常的页表项当前有效。
- `PFAULT_WRITE`：写访问触发，对应 store page fault。
- `PFAULT_USER`：异常来自用户态。

调用方必须先判断写入类型，再把 `tf->tval` 作为故障地址传给 `do_pgfault`。

### 5.2 `PTE_COW`

在 `mmu.h` 中分配软件专用页标志：

```c
#define PTE_COW 0x100
```

约定：

- `PTE_COW` 只能表示该页面由多个进程共享且写时复制。
- 带 `PTE_COW` 的用户可写 VMA 对应 PTE 必须是只读的，即清除 `PTE_W`。
- 不得把 `PTE_COW` 用于普通惰性分配。
- 复制完成后清除新私有页面的 `PTE_COW`，恢复 VMA 允许的读写权限。
- 修改 PTE 后必须刷新对应地址的 TLB。

### 5.3 `do_pgfault` 固定原型

```c
int do_pgfault(struct mm_struct *mm, uint32_t error_code, uintptr_t addr);
```

约定：

- `mm == NULL` 或地址不属于合法 VMA 时返回 `-E_INVAL`。
- 普通未映射页：分配页面并建立映射。
- COW 页：完成复制后返回 0。
- 分配失败返回 `-E_NO_MEM`。
- 返回 0 前必须保证 PTE 和 TLB 状态一致。

## 6. 系统调用 ABI

### 6.1 寄存器约定

| 寄存器 | 含义 |
|---|---|
| `a0` | 系统调用号；返回时存放返回值 |
| `a1` | 参数 0 |
| `a2` | 参数 1 |
| `a3` | 参数 2 |
| `a4` | 参数 3 |
| `a5` | 参数 4 |

用户态入口已经由 `code/user/libs/syscall.c` 负责保存参数并执行 `ecall`。内核不得依赖用户栈取出系统调用参数，只能读取 `current->tf->gpr`。

### 6.2 系统调用号

| 名称 | 编号 | 内核动作 |
|---|---:|---|
| `SYS_exit` | 1 | `do_exit(arg[0])` |
| `SYS_fork` | 2 | `do_fork(0, 0, current->tf)` |
| `SYS_wait` | 3 | `do_wait(arg[0], (int *)arg[1])` |
| `SYS_exec` | 4 | 按 `exec` 参数约定调用 `do_execve` |
| `SYS_yield` | 10 | `do_yield()` |
| `SYS_kill` | 12 | `do_kill(arg[0])` |
| `SYS_getpid` | 18 | 返回 `current->pid` |
| `SYS_putc` | 30 | `cputchar((int)arg[0])` |
| `SYS_pgdir` | 31 | `print_pgdir()` |

未登记或越界的调用号返回 `-E_INVAL`。

### 6.3 内核分发函数

公开入口：

```c
void syscall(void);
```

所有处理函数使用统一签名：

```c
static int sys_xxx(uint64_t arg[]);
```

`syscall()` 从 `current->tf` 取出编号和参数，调用对应 `sys_xxx`，再把返回值写回 `current->tf->gpr.a0`。

系统调用层的职责只有参数整理、基本边界检查和返回值写回。真正的进程语义由 `do_*` 函数实现。

## 7. 进程管理接口

以下原型已经在 `proc.h` 中固定：

```c
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags);

int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
int do_exit(int error_code);
int do_yield(void);
int do_execve(const char *name, size_t len,
              unsigned char *binary, size_t size);
int do_wait(int pid, int *code_store);
int do_kill(int pid);
```

### 7.1 返回值约定

| 函数 | 成功 | 失败 |
|---|---|---|
| `kernel_thread` | 返回新 pid | 返回负错误码 |
| `do_fork` | 父进程返回子 pid，子进程返回 0 | 返回负错误码 |
| `do_execve` | 返回 0 | 返回负错误码 |
| `do_wait` | 成功回收一个子进程后返回 0 | 返回负错误码 |
| `do_yield` | 返回 0，并设置 `need_resched` | 当前骨架不返回错误 |
| `do_kill` | 返回 0 | 返回负错误码 |
| `do_exit` | 不返回 | 不返回 |

### 7.2 调用约束

- `do_fork(0, 0, current->tf)` 用于用户态 `fork`。
- 内核线程创建可以传入非空的 `stack` 和 `tf`，由 `do_fork` 决定上下文。
- `do_wait(pid, code_store)` 中 `pid == 0` 表示等待任意子进程；用户态 `waitpid(-1, ...)` 按无效 pid 处理。
- `do_wait` 写入 `code_store` 前必须通过 `user_mem_check` 检查用户指针。
- `do_exit` 只能由当前进程调用，不能用于回收其他进程。
- `do_kill` 只能设置退出请求并唤醒目标，不能直接替目标释放内核栈。
- 所有接收用户指针的系统调用都必须在进入 `do_*` 语义前检查地址空间。

## 8. 内存复制接口

以下原型已经在 `pmm.h` 和 `vmm.h` 中固定：

```c
int copy_range(pde_t *to, pde_t *from,
               uintptr_t start, uintptr_t end, bool share);

int dup_mmap(struct mm_struct *to, struct mm_struct *from);
```

`copy_range` 的 `share` 约定：

- `share == false`：深复制物理页面，新页面引用计数初始为 1。
- `share == true`：共享原页面，增加原页面引用计数，并把可写共享页标记为 `PTE_COW`。
- 地址区间必须按页对齐，并满足 `start < end`。
- 中途失败必须回收已分配的页面和已增加的引用计数。

`dup_mmap` 约定：

- 复制全部 VMA，保持区间顺序和权限。
- COW 开启时，调用 `copy_range(..., true)`。
- 返回 0 表示整个地址空间复制成功；失败时不能留下半完成的新地址空间。

## 10. 修改接口的规则

1. 先在群里说明需要修改哪个签名或结构体。
2. 由接口负责人一次性修改头文件、调用方和本文档。
3. 在同一次提交中完成，不允许先改声明后留到下次。
4. 修改 trapframe、`do_pgfault` 或 `do_*` 签名后，必须通知三人重新拉取。
5. 不允许在个人分支里私自增加第二套接口。
